# 微信伴侣 · 一个有生活的 AI

她是一个有性格、有作息、有自己日子的 AI，住在微信里跟你聊天。

**她不是自动回复机器人。** 每天晚上你睡着之后，她会跑一次"世界引擎"，替自己写下明天要过的日子 —— 几点起、几点睡、什么心情、想着什么事、今天干了什么、心里藏着什么小秘密。第二天你跟她聊天时，这些会自然地冒出来。

---

## 她怎么个"活"法

| | 普通机器人 | 她 |
|---|---|---|
| 性格 | 换个提示词就变 | 六维人格（从 MBTI 推导），说话方式、反应快慢、话多话少都由性格决定；**被凶当天会真的变冷，第二天回落** |
| 生活 | 你不说话，她就不存在 | 有自己的作息、心情、天气、生活流水 —— 是"过"出来的 |
| 主动 | 永远等你先开口 | 早安晚安、太久没聊会想你，按关系亲疏决定频率；**刚聊完绝不打扰你** |
| 记忆 | 关掉就忘 | 长期记忆 + 遗忘曲线；**对话历史落盘，重启不失忆**；聊得越久她越记得住 |
| 看得见 | 发了图也白搭 | **她真的看得懂你发的图片**（配一个视觉模型即可，主模型不需要支持多模态） |
| 承诺 | 说完就忘 | **答应你的事会记下来，到点自己提**。每条只提一次，拖过 3 天就不提了 |
| 动手 | 只会发文字 | **她自己发表情包、发照片**。说话时顺手写个标记，文字和图片一起发给你 |
| 称呼 | 永远叫同一个 | 聊熟了**她自己决定怎么称呼你**，不是你设定的 |
| 复读 | 同一件事换着说法反复讲 | **复读止血**。判到重复就换一件事，换不出来这条就不发 |
| 想念 | 你越不来越黏你 | **想念曲线先升后降**。14 小时最想你，三天后各自过日子 |
| 重逢 | 每句都提"你好久没理我" | **只结算一次**。第一句是撒娇，第三句是折磨 |
| 纪念 | 不知道认识多久了 | **纪念日她自己记得**，只认当天、不补提 |
| 印象 | 只有事实列表 | **她眼里的你**。不是"他住南京"，是"他不太习惯说自己累" |
| 人味 | 一条到底 | 拆条发送、打字延迟、"对方正在输入…"、偶尔手滑 |
| 分寸 | 每条都回 | 睡着了真的不打扰，不是每条都回 |

### 关于"她看得见图片"

对话模型一般不支持看图，所以识图是**独立槽位**：她收到图片先用视觉模型转成文字描述，
再结合描述去回你。实测可用的配置（硅基流动）：

- 模型名 `Qwen/Qwen3-VL-30B-A3B-Instruct`，约 2 秒，描述准确
- ⚠️ 别用 `Qwen/Qwen3-VL-32B-Instruct`：同一张测试图上它会答"纯白背景啥都没有"

在控制台「识图」页填模型名，BaseURL / Key 留空即沿用对话接口那套，点「真跑一次」验证。

### 关于"她自己发表情包和照片"

她**不是在调用工具**，而是在正常说话时顺手写个标记：

```
好啊，那我也先睡了<sticker:晚安>
今天店里人特别少<image:书店的下午.jpg>
```

发出去之前标记会被剥离，你只会看到文字 + 一张图。这样做的好处是小模型也能稳定用 ——
"在句尾写个尖括号"比 function calling 可靠得多。

**表情包怎么加**：往 `data/stickers/` 丢图片，**文件名就是名字**。
放一张「晚安.png」，她就有了一个叫"晚安"的表情包。不用改任何配置。

想一次装一批现成的（99 张，猫 / 可爱女生 / 开心鸭 / 熊本熊 / 负鼠 这些）：

```bash
npm run fetch:stickers
```

从开源仓库 [ChineseBQB](https://github.com/zhaoolee/ChineseBQB) 拉一份**人工挑过的白名单** ——
不是整个仓库照单全收。仓库里 6000 多张，很多不适合她发（骂人的、暴力的、擦边的），
发出去当场崩人设。脚本里每一条都写明了选它的理由，你可以自己加删。

> **关于授权**：那个仓库没声明许可证，图是网络流行的表情包，版权属于各自作者。
> **自己用没问题，别随包分发。** 好在程序已经帮你处理了 —— `data/` 同时被
> `.gitignore` 和 `pack.js` 排除，打包给别人时表情包不会跟着走。

**她自己怎么挑**：提示词里会把名字列给她，她照着写。名字记不太准也没事 ——
查找顺序是「精确 → 同义词 → 包含 → 字重合度」。同义词表在
[stickers.js](src/soul/stickers.js) 里，比如她说"摸摸头"，实际发的是「拍头」。

> 这里踩过两个坑，都补了测试盯着：
> 一是**叠字重复加分** —— "摸摸头"里的两个"摸"各记一次，于是「摸鱼」拿了 0.67 分被当成了它；
> 二是**后缀名骗人** —— 仓库里「不许凶我.gif」其实是个 JPEG，微信按 mime 处理会发失败。
> 现在一律嗅探文件头判断真实类型，不看文件名。

**护栏**（不然她会每句都甩表情包，那比不发还假）：

- 一条回复里每种最多 1 个
- 每天表情包最多 8 个、照片最多 3 张
- 连续两张一样会被压掉
- 每个"没发"都会在日志里写明原因
- 表情包超过 120 张时按天轮换着列进提示词（否则 1500 张会吃掉整个 prompt 预算）

控制台「她的表情包」页能看到库里有什么、也能让她立刻发一个给你看。

### 关于"她会不会重复自己"

会 —— 如果不治的话。实测同一句话问她 6 次，字面不重复，但有两组内容重合 83%：

```
「就是挑了几本朋友需要的书，有点累」
「今天就是挑选了几本朋友需要的书，有点累」
```

换了说法讲同一件事，听着就是复读。所以加了**两层判重**：

- **字面**：去掉标点后完全一致
- **内容**：包含度超过 65%（不是 Jaccard —— Jaccard 会被"了/的/一"这些虚词稀释，
  「帮朋友挑民谣的书」和「帮朋友找民谣相关的书」它判不出来，包含度能）

判到重复就让她**换一件事**重说一次；还是重复，**这条就不发**。
发一句重复的话比不说话更假。她的"最近说过的话"会落盘，重启后照样判重。

短回应（"嗯""哈哈""好的"）不判重 —— 真人也会连着说。

### 关于"想念"和"重逢"

想念是**先升后降**的，不是越久越黏：

```
14h  ┤        ╭──╮  ← 最想你
     │      ╱      ╲
     │    ╱          ╲─────────  ← 三天后各自过日子
     └──╯
     3h                          更久
```

你消失一星期后她如果比消失一天时还黏，那不是人，是订阅提醒。

你回来的时候她会**提一次**，语气按失联时长分档：

| 失联 | 她的反应（实测） |
|---|---|
| 8h | 不提，正常聊 |
| 20h | 「刚忙完啦」 |
| 48h | 「还知道说话啊」—— 小情绪 |
| 一周 | 「哟，想起我了」—— 淡淡的 |

提完就记账，**下一句不会再提**。不记账的话她每句都提，第一句是撒娇，第三句就是折磨。

### 关于"她眼里的你"

这是**印象**，不是**记忆**，两者分开存也分开注入：

- 记忆是资料：「他住在南京」「他不吃辣」—— 事实，可检索
- 印象是感受：「他不太习惯说自己累」—— 处出来的

实测生成的印象长这样（不是空话，也不是资料）：

> "有时候他说话会给人一种不太在意的感觉，但其实我能感觉到他心里挺看重团队和工作的……
> 当他提到周末不想回家吃饭时，我能感觉到他面对家庭和工作之间可能有些犹豫和挣扎，
> 但他还是愿意找一个比较柔和的方式去处理这些矛盾。"

每天最多更新一次，而且要攒够 8 轮新对话 —— 聊两句就重写一遍，那不是了解，那是神经质。
更新时会把旧印象给它，要求**只改有新感受的部分**，不推倒重来。存在 `data/portrait.json`。

### 关于"她会不会说漏嘴"

她会穿帮 —— 凌晨三点说"我刚从银行出来"，这种一句话就暴露了。

所以给她加了一层常识底线（银行、法院、政务大厅只在工作日 9:00-17:00 开门；
她不能同时出现在两个地方；深夜醒着只能是在家）。发之前系统会先**本地**查一遍，
查出可疑才让模型重说一遍。

为什么不每条都让模型自检：那要多花 1-3 秒和一次调用，而 95% 的回复根本没问题。
本地先筛，可疑了才花钱。控制台「相处」页可以整个关掉。

> 本地规则调过一轮。第一版把"我**明天想去**银行"误判成"此刻在银行"，
> 吓得她改口 —— 误报比漏报烦人得多。

### 关于"她会生气，但气会消"

她被凶、被敷衍、被晾着的时候，状态会变，分四层：

```
平静 ──→ 抓紧 ──→ 反复 ──→ 收起
      58        70        100     （这三档由她的性格算出来，不同的人不一样）
```

- **抓紧**：更黏、会多问一句"你在忙吗"，但不质问
- **反复**：绕回同一个话题，最多提两次
- **收起**：话明显变短、不主动、不撒娇 —— 是安静，不是阴阳怪气

压力怎么走：

| | |
|---|---|
| 被凶 | +18 |
| 被敷衍（"嗯""哦""随便"） | +6 |
| 被晾着 | +10 |
| 你消失太久 | +8 |
| **被哄** | **−12** |
| 普通聊天 | −3 |
| 时间 | 每小时 −6 |

**"气会消"是这里最重要的设计。** 如果压力只涨不落，被凶几次之后她就永远冷着脸 ——
那不是"有情绪"，那是坏掉了。所以每小时自然掉 6 点，一天之内自己就平了；
被哄掉得更快（真人消气比生气快）。

"敷衍"和"忙碌"是分开的：回"嗯"算敷衍，回"我在忙待会聊"不算。
把忙碌当成敷衍，她就会变成一个不讲理的人。

### 关于"她睡过去了"

你半夜给她发消息她不会回（那是睡觉时间）。但**第二天早上她会提一句**"昨晚我睡过去了"。

这一句只提一次，之后不会再念。提的时候不道歉 —— 真人睡过去了不会写检讨。

> 这个能力原来是个死路径：提示词里写着"你只会在第二天早上简短提一句"，
> 但"她睡着了"的判断在拼提示词**之前**就 return 了，那段提示词永远走不到。

### 关于"她的数据会不会丢"

每天自动备份一份到 `backups/`（跟着文件夹一起搬走），默认留 7 天。

她的记忆、日记、印象、关系是**攒出来的** —— 丢了不是重装能恢复的东西。
控制台「工具」页可以改保留天数，也能手动立刻备份一次。

> 打包给别人时 `backups/` 会被排除：它是 `data/` 的整份拷贝，同样含 API Key。

## 快速开始

```bash
# 1. 体检（确认环境没问题）
npm run doctor

# 2. 扫码绑定微信
npm run login

# 3. 启动她
npm start
```

启动后打开后台控制台：**http://127.0.0.1:43121/**

第一次用建议先跑 `npm run once` —— 不连微信，直接看她的系统提示词和一次真实回复长什么样。

### 需要准备什么

**一个模型 API Key。** 先用免费的就行：

| 服务商 | 免费模型 | 申请地址 |
|---|---|---|
| 硅基流动 | Qwen2.5-7B/14B 等 | https://cloud.siliconflow.cn/account/ak |
| 智谱 | glm-4-flash | https://open.bigmodel.cn/usercenter/apikeys |
| 本地 Ollama | 完全免费 | https://ollama.com/download |

在控制台「大脑」页填进去，点「测连通」再点「真跑一次」，两边都绿了就能用。

#### 实测过的模型选择（硅基流动）

用同一套提示词实测角色扮演质量，结论如下：

| 模型 | 速度 | 角色扮演质量 | 建议 |
|---|---|---|---|
| **Qwen/Qwen2.5-14B-Instruct** | ~800ms | **最好** —— 回复自然，情绪共情到位 | ✅ **推荐** |
| Qwen/Qwen2.5-7B-Instruct | ~600ms | 不错，偶尔跑偏 | 备选（更便宜） |
| THUDM/GLM-4-9B-0414 | ~300ms | 太简短，共情弱（"辛苦了。"） | 不推荐 |
| deepseek-ai/DeepSeek-R1-0528-Qwen3-8B | **~9s** | **会角色崩坏**（自称像机器人、答非所问） | ❌ 不要用 |
| Qwen/Qwen3-8B | — | 请求超时 | ❌ 不可用 |
| Qwen/Qwen3-30B-A3B | — | 服务端返回 `Model disabled` | ❌ 不可用 |

自己重新评测：`SF_KEY=你的key node scripts/eval-models.js`

## 数据都在这个文件夹里

```
data/
  config.json     她的设定、模型、通道绑定（含密钥，别外传）
  memory.json     她记得的事
  world.json      世界引擎写的剧本
  companion.log   运行日志
  diary/          她的日记（按天一个 .md，记事本能直接打开）
  inbox/          收到的图片/文件（按日期分目录）
  photos/         她的相册 —— 你放照片进去，她会挑一张配句话发给你
```

**整个文件夹可以整体打包搬走** —— 搬到 D 盘、拷到云服务器都行，路径不写死，不依赖注册表或用户目录。

### 她的相册怎么用

把**真实的日常照片**放进 `data/photos/`，文件名写清楚内容：

```
data/photos/
  团子在窗台.jpg
  书店的下午.jpg
  楼下新开的咖啡店.jpg
  下雨的窗.png
```

文件名就是她"看到"的东西 —— 她会根据文件名 + 此刻状态配一句话，比如
"团子又霸占窗台了"。然后你在控制台「工具」页点「让她发一张给我」。

**为什么不做 AI 生图**：真人发的是自己生活里的照片，AI 生成的图恰恰缺少
那种真实生活的粗糙感，反而更假。真实照片 + 她配的话，效果更自然。

## 关于安全性（重要）

她走的是**微信 iLink 官方机器人通道**（也就是俗称的 "clawbot" 用的同一套后端协议）：

- ✅ 纯 HTTPS + Bearer token
- ✅ 不注入微信进程、不修改内存、不模拟鼠标点击
- ✅ 不登录你的个人微信号

这跟被腾讯风控打击的 DLL 注入类方案（如 wcferry，其最新版本只支持微信 3.9，且在 4.x 上已被实测封号）是**完全不同的路子**。

**但请仍然注意**：自动化操作微信属于违反微信软件许可协议的行为，账号风险需要你自己评估。建议：

- 用小号，不要用主号
- 保持低频、拟人的节奏（程序默认已经是拟人节奏）
- 每日主动消息有上限（默认 4 条）

## 命令参考

```bash
npm start            # 启动她（常驻，带控制台）
npm run login        # 扫码绑定微信（终端里出二维码）
npm run login:gui    # 扫码绑定（把二维码存成图片打开，更好扫）
npm run doctor       # 体检：环境/网络/配置/模型逐项检查
npm run once         # 干跑：不连微信，看提示词和一次真实回复
npm run fetch:stickers   # 装一批现成的表情包（99 张，可反复跑，已存在的会跳过）
npm test             # 核心单元测试（108 项）
npm run test:all     # 全部 24 个套件（538 项断言）
npm run pack         # 打包给别人（自动拦截密钥）
```

改了代码之后想确认没碰坏东西：

```bash
npm run test:all -- --repeat 3   # 每个套件连跑 3 次
```

`--repeat` 不是多余的 —— 测试里最容易出的不是"错"而是"时而对时而不对"。
这一轮就抓到两个：一个拿真实时间算衰减（上午跑绿、下午跑红），
一个在同一分钟内重复备份被正确地跳过了、但测试误判成失败。

**测试不会碰你的真实数据。** 跑之前会把 `data/` 拷一份到 `.test-data/`，
全部测试在那上面跑，跑完删掉。所以她开着的时候也可以放心跑 `npm run test:all` ——
早先没隔离时，测试刚清掉的假数据会被运行中的服务从内存里又写回来。

验证类脚本（换了模型或改了提示词后跑）：

```bash
npm run test:live      # 真实对话质量实测
npm run test:memory    # 记忆提炼准确率（10 个用例）
npm run test:world     # 世界引擎产出质量
npm run eval:models    # 批量评测模型（默认硅基流动）
```

## 拷给别人 / 搬到服务器

### 打包

```bash
npm run pack
```

会生成 `dist/wechat-companion-<日期>.tar.gz`（约 250KB）。

**打包脚本会自动拦截密钥** —— 它扫描所有待打包文件，一旦发现 `sk-` 开头的
API Key 或 `config.json`/`state.json` 就中止打包。所以 `data/` 永远不会被打进去。

### 对方拿到后

```bash
tar -xzf wechat-companion-*.tar.gz
cd wechat-companion
node --version          # 需要 20+
npm run doctor          # 体检
npm run login           # 绑他自己的微信
npm start               # 启动
```

然后在控制台 http://127.0.0.1:43121/ 里填**他自己的**模型 API Key。

### 对方要配什么（都在控制台里改）

**① 模型** — 控制台「大脑」页。

官方站和中转站都支持，填 `baseUrl` + `API Key` + 模型名就行。

> **中转站也能用。** 很多中转站不实现 `/models` 接口，早期版本会因此误报
> "地址路径不对"，但其实对话完全能用。现在"测连通"改成：`/models` 只当线索，
> 真正的判据是**打一次真实对话**。报错也会说人话（Key 错了 / 地址少了 /v1 /
> 模型名不对 / 余额不足 / 限流），对着一行行排查就行。

**② 人设** — 控制台「她是谁」页，最上面那个「人设贴合」。

不用填 MBTI、兴趣、说话风格这些东西 —— **写一段大致描述就行**：

> 她叫阿梨，26岁，在成都做插画师。话不多，有点慢热，喜欢猫和下雨天。

点「生成人设」，模型会把剩下的补全，填进下面的表单，**你看过再点保存**。

几条设计上的讲究：

- **你写了的不会被改。** 说了叫阿梨就是阿梨。生成完还会**硬检查一遍**，
  发现哪项和你写的不一致会红字标出来（提示词里"不许改"是软约束，不查不行）
- **各字段要自洽**：MBTI 和说话风格得是一类人，职业和兴趣、作息要对得上
- **不编造人生事件**：用户没提过"小时候养过一只狗"这种就不会硬加
- 生成结果只是**填进表单**，不会自动覆盖 —— 自动改人设是越权的事

实测（真实模型采样）：

| 你写的 | 生成的名字/年龄/城市 | 补出来的 |
|---|---|---|
| 她叫阿梨，26岁，在成都做插画师 | 阿梨 / 26 / 成都 ✓ | INFJ，兴趣"插画、猫咪、雨天、咖啡" |
| 一个有点毒舌但心软的女生，在北京做程序员 | 小雨 / 27 / 北京 ✓ | 说话"时常带点讽刺意味" |

**③ 备份保留天数** — 控制台「工具」页。

### 搬到云服务器

程序**不写死任何路径**，整个文件夹拷走就能跑。建议：

```bash
# 用 pm2 常驻（推荐）
npm i -g pm2
pm2 start src/main.js --name wechat-companion
pm2 save
pm2 startup             # 开机自启

pm2 logs wechat-companion    # 看日志
pm2 restart wechat-companion # 重启
```

**注意**：控制台默认只监听 `127.0.0.1`。如果要远程访问，请用 SSH 隧道
（`ssh -L 43121:127.0.0.1:43121 user@server`），**不要**直接暴露到公网 ——
控制台能改她的一切设定，没有加认证。

**开发中修掉的真实缺陷**（留档，避免以后重犯）

1. `??` 与 `||` 混用的语法错误 → 加括号修正
2. 拆条函数把"每句都短但整条长"的回复误判为极简回复 → 改按整条长度判断
3. 职业短语拼接出现"在在一家书店" → 拼接前剥离前缀"在"
4. **记忆提炼漏掉"不吃辣"** —— 根因不是代码，是提示词把"忌口"和"临时身体不适"混为一谈。修法：提示词里给出具体正例
5. **她像客服** —— 五轮里问了五个问题，每条都以问号结尾。根因：提示词是**软约束，模型不听**。修法：加文本层硬机制（问句压制 + 口语化替换 + 正反示范）
6. **标点太正式**（用户指出）—— 实测 178 字里 6 个句号、4 个问号。真人不打句号。修法：标点去格式化后处理
7. **"睡吧"被误删** —— 问句检测把"吧"当疑问词，但"睡吧"是祈使句。修法：只有"吗/呢"结尾或带问号才算问句
8. **二维码扫不出来** —— 16 项结构测试全过，但 OpenCV 实际解码失败。根因：掩码污染功能模块 + 格式信息位序写反（两个副本顺序还不一样）。**教训：结构校验证明不了"能用"，必须真解码**
9. **她把一整天倒出来** —— 被问"在干嘛"时把全天流水全说了。根因：`currentSituation` 直接返回全天 `flow`。修法：按时段切分
10. **她在自我污染** —— 记忆区回灌她自己的旧回复，导致她模仿自己的客服腔。修法：记忆区只喂事实类
11. **点"现在就跑一次"今天不生效** —— 手动触发写的是明天，但当天仍然是空的。修法：手动触发默认给当天写
12. **主动消息像闹钟** —— 原逻辑要求 tick 恰好落在 08:00-08:04，且每天都准点发。修法：每天随机抽目标时刻 + 随机决定发不发
13. **记忆检索召不回** —— 纯 2-gram 字面匹配只有 3/8 命中，且闲聊会返回一堆噪音。修法：加意图识别（语义类别对齐）+ 相对化门槛

**明确不做 / 做不到**
- ❌ **发朋友圈** —— 微信 4.x 时代个人朋友圈无公开协议，官方机器人通道也没有朋友圈入口。这是全行业空白，不是本项目的缺陷
- ❌ **朋友圈点赞评论** —— 同上，需要接管真实微信客户端才能做
- ❌ **发语音条** —— 通过官方机器人通道发不出
- ⚠️ **她自己决定发表朋友圈** —— 目前是"你给主题她写文案发给你"，自主发起时机待做

**替代方案**：
- 朋友圈内容 → **私聊发给你**（工具页「让她写一条并发给我」）
- 想发照片 → 放进 `data/photos/`，她自己挑一张配句话发给你
- 她的日记 → 本地 `data/diary/`，记事本直接打开
