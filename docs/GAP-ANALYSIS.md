# 与参考项目的功能差距（2026-09-19 复核）

> 这份是对**源码**逐项核对的结果，不是印象。
> 主要依据：`_reference/thalamus/src/feature-status.js`（它自己的权威功能清单，207 行，
> 每项都标了 done/partial/planned/shelved）。另两个仓库已单独核对，见最后。

## 先说一件容易搞错的事

三个"参考项目"里**只有一个是同类**：

| 仓库 | 实际是什么 | 能不能比 |
|---|---|---|
| **thalamus** | 独立伴侣程序（11,728 行） | 唯一的同类，主参照 |
| clawbot | 把 DSH 编码助手接进微信的**网关插件** | 不是一个赛道 |
| wechat-bridge | 同上，另一种实现 | 不是一个赛道 |

后两个是"微信 ↔ AI 编码助手"的桥：工作区切换、`/new` `/stop` 会话控制、
工具调用提示、会话通知推送。它们**没有性格、记忆、心情、主动消息**这些概念。
拿它们的功能表来比"她还缺什么"是错位的。

但它们有三样东西**可以借鉴**，见文末。

## 一、上次报告之后已经补齐的

| 能力 | 参考项目状态 | 我们现在 | 说明 |
|---|---|---|---|
| 表情包系统 | partial（它自己卡在"通道待验证"） | **done** | 我们真的发出去了，还带模糊匹配和护栏 |
| 她自己动手（指令协议） | done | **done** | 支持 `<sticker:>` `<image:>` `<remember:>` |
| 复读止血 | done | **done** | 它用便宜模型判"是不是同一件事"，我们用字面＋包含度 |
| 想念曲线 | done | **done** | 先升后降，重逢只结算一次 |
| 她眼中的你（画像） | done | **done** | 每日最多一次，和记忆分开存 |
| 她自主发图 | partial（它明确写"还差的只有她自己决定发"） | **done** | 这一项**我们超过了参考** |

> 复读止血的实现方式不同：它调便宜模型判语义，我们用字符包含度。

> 好处是零依赖、零成本、不怕模型抽风。实测抓得住 83% 重合的换说法重复。

## 二、真实缺失

### 已补齐（本轮）

| # | 能力 | 参考项目 | 我们的实现 | 验证方式 |
|---|---|---|---|---|
| 1 | **四层变形状态机** | done | **done** | 接上了压力累加器；54 项单测 + 16 项端到端 |
| 2 | **常识底线 + 发前自检** | done | **done** | 39 项单测 + 13 项接线（假模型服务实测改口） |
| 3 | **早上"昨晚我断片了"** | done | **done** | 22 项单测；原来提示词和代码没接上 |
| 4 | **自动备份** | done | **done** | 20 项单测，含逐字节比对恢复 |
| 5 | 模型接入吃中转站 | — | **done** | 23 项，用真 HTTP 服务模拟各种服务商 |
| 6 | 人设贴合（模板→完整人设） | 女娲 | **done** | 68 项单测 + 真实模型三次采样 |

**第 1 项原来是什么样**：`persona.js` 算出了三个阈值，但全项目搜索只在那三行
出现过 —— 没有累加器、没有状态切换，纯粹是摆设。现在接上了：

```
平静 → 抓紧(58) → 反复(70) → 收起(100)
  被凶 +18   被敷衍 +6   被无视 +10   你消失太久 +8
  被哄 -12   普通聊天 -3
  每小时自然衰减 -6（所以气不会过夜）
```

**这里踩到的坑值得记下来**：第一版把**所有非敌意的话**都当成"被哄"（-12），
于是"被凶一次 +18，随便回一句 -12"，压力永远涨不起来 —— 状态机接上了但等于没接。
是端到端测试（连凶四句看层有没有变）把它抓出来的，单测全绿。

**第 2 项的取舍**：参考项目每条消息都调模型自检，我们改成**本地先查（免费、必跑）**，
只有查出可疑才调模型复核。理由是每条都自检要多花 1-3 秒和一次调用，而 95% 的回复
根本没问题。本地规则调过一轮 —— 第一版把"我明天想去银行"当成"此刻在银行"误报了。

**第 5 项原来是什么样**：测连通只打 `/models`。中转站**大多不实现这个接口**，
所以中转站用户会看到"地址路径不对"，但对话其实完全能用 —— 这是最劝退的一种误报。
现在 `/models` 只当线索，真正的判据是打一次最小对话。

## 三、我们比参考做得好的地方

1. **零依赖** —— 它需要 Python sidecar + faiss + bge-m3 + mem0。
   我们是 61 个 JS 文件、无 `node_modules`，整个文件夹拷走就能跑。
2. **她自主发图已经打通** —— 参考项目这项还标着 partial。
3. **表情包真的能发** —— 参考项目标 partial，我们自己实测跑通了。
4. **复读止血零成本** —— 它每次判重要多调一次模型。

## 四、从另外两个仓库值得借的（就三样）

| 能力 | 出处 | 为什么值得 |
|---|---|---|
| **入站白名单 fail-closed** | clawbot / wechat-bridge | 它们是"留空=拒绝所有人"，我们是"留空=谁都回" |
| **配置导出/导入** | 都有 | 换机器、搬家时不用手抄 |
| **崩坏日志隔离自愈** | wechat-bridge | 状态文件坏了自动改名重建，我们现在是读不到就当空 |

> 我们**已经有**的两项（容易以为没有）：
> - 入站消息去重：`companion.js:225` 用 `state.seen` 按 `clientId` 去重
> - 会话过期处理：`companion.js:210` 遇 `errcode -14` 暂停 60 分钟
>   —— 和 wechat-bridge 的处理方式一致。

## 五、核对方法与局限

- 参考项目那一侧：直接读它自己的 `feature-status.js`（它标注得很诚实，
  连"卡在哪"都写了），不是从 README 的宣传语推断。
- 我们这一侧：**全项目正则搜索 + 逐条打开命中行确认真伪**。
  这一步是必须的 —— 第一遍粗搜出来的 15 项里，**有 8 项是假阳性**
  （比如 `period` 匹配到了"时段"而不是"生理期"）。
- 局限：`clawbot` / `wechat-bridge` 两个仓库只读了 README 和文件清单，
  没有逐行读源码；它们的定位差异很大，细读的收益有限。
- 另一处更正：一度以为"每日主动消息上限"没有执行，复查发现
  `companion.js:686` **确实在执行**，是前一次搜索被 `Select -First 12` 截断导致的误判。
